# 涂鸦精灵（painting-sprite）可行性分析与技术方案

> 版本：v0.1（草案，待评审）
> 日期：2026-09-29
> 目标平台：iOS / Android / macOS / Windows（Flutter 单代码库）

---

## 0. 一句话结论

**技术上可行，无不可逾越的障碍；真正的生死题不是"能不能做出来"，而是"每次许愿都在烧钱"的商业模式。** 解法是三层动画引擎分层：免费的端侧程序化动画打底 + 近零边际成本的自部署人形动画做主路径 + 云端图生视频做付费亮点。详见 §3.5 与 §4。

## 1. 需求拆解

| 编号 | 功能 | 输入 | 输出 | AI 依赖 |
|---|---|---|---|---|
| F1 | 自由绘画 | 触控/鼠标 | 涂鸦 PNG | 无（纯本地） |
| F2 | 线稿涂色 | 文本或语音描述 | 可打印线稿 → 打印 → 纸上涂色 → 拍照回传 | LLM（提示词改写）+ 图像生成（线稿）+ 图像处理（拍照校正/抠图） |
| F3 | 语音许愿变 5 秒动画 | 涂鸦 PNG + 语音愿望 | 5 秒动画（MP4/GIF） | ASR + LLM（愿望→视频提示词）+ 图生视频模型 + TTS |
| F4 | 四端部署安装 | — | App Store / 各应用市场 / 桌面分发 | — |

**核心链路（F2 → F3 串起来就是产品的"魔法时刻"）：**

```
孩子说"我要一只小恐龙"
  → ASR 转文本
  → LLM 改写成线稿提示词（儿童安全过滤）
  → 图像模型生成线稿（白底黑粗线）     [¥0.1~0.3/张]
  → 家长打印 → 孩子纸上涂色
  → 拍照回传 → 透视校正 + 背景去除
  → 孩子对着涂好的画许愿"让它跳舞吧"
  → LLM 生成视频提示词
  → 图生视频模型 → 5 秒动画            [¥1.5~7.5/条，路线差异巨大]
  → 播放 + TTS 语音喝彩
```

## 3. 功能技术可行性

### 3.1 画板（F1）——零风险

- `CustomPainter` + 笔画模型（List<Stroke>），天然支持撤销/重做（栈结构）。
- `RepaintBoundary.toImage()` 导出 PNG，全平台一致。
- **涂色模式的关键算法：泛洪填充（flood fill）**。坑点：抗锯齿边缘会在色块边界留白边。业界标准解法是"扩容扫描"（scanline fill + tolerance + 像素扩边），纯 Dart 可实现，1080p 图毫秒级。这是本 App 少数需要"真算法"的地方，但都是 30 年前的成熟算法。

### 3.2 线稿生成（F2 前半）——成熟 API，成本极低

- 提示词模板化：`"children's coloring book page, {subject}, thick black outlines, pure white background, no shading, no color, simple composition for kids"`。
- 模型选择（2026-09 实时行情）：

| 模型 | 价格 | 备注 |
|---|---|---|
| 豆包 Seedream 5.0 flash | ¥0.12/张 | 性价比首选 |
| 可灵 Image 2.1 | ¥0.10/张（文生图） | |
| Seedream 5.0 pro | ¥0.30/张 | 质量更好 |

- **风险点**：生成"可涂色"的线稿要求线条闭合（不然涂色会漏色）。缓解：提示词约束 + 后处理（形态学闭运算，纯 Dart/服务端 OpenCV）+ 生成 2 张让孩子挑。质量不达标时备选方案：ControlNet-lineart 自部署，可控性最强但要多养一个模型服务。

### 3.3 语音三件套——全是白菜价

| 环节 | 方案 | 成本 |
|---|---|---|
| ASR 语音识别 | 移动端系统级（免费）；桌面端录音上传豆包 ASR / Whisper API | ≈¥0.001~0.003/次，忽略不计 |
| LLM 愿望理解 | GLM-4-Flash（有免费档）/ 豆包 Lite：把童言童语转成规范提示词 + 安全过滤 | ≈¥0.001/次，忽略不计 |
| TTS 语音反馈 | flutter_tts 调系统语音（免费）；需要童趣音色时用云端 TTS | 云端 ¥0.05/次 |

**结论：语音环节在成本模型里可以直接四舍五入为 0。钱都烧在视频上。**

### 3.4 拍照回传（F2 后半）——工程问题，不是科学问题

纸上涂完色拍照回来，需要三步处理：
1. **透视校正**：检测纸张四角（可让孩子拖四个角点辅助，比全自动更稳）→ 透视变换；
2. **光照归一化**：白平衡 + 亮度拉伸，让"台灯下的黄纸"变回"白纸"；
3. **背景去除**：把纸外的桌面裁掉，只留画。简单场景纯算法可解；复杂背景用 rembg 类模型（自部署，BRIA RMBG 等开源权重）。

难度评估：中等。每一步都有成熟方案，难点在"儿童拍照条件恶劣"的鲁棒性——所以产品上要用"拖角点确认"这种半自动交互兜底，别追求全自动。

### 3.5 动画引擎三路线对比（F3 核心，本项目最重要的技术决策）

| 维度 | 路线 A：云端图生视频 API | 路线 B：Meta AnimatedDrawings 自部署 | 路线 C：端侧程序化动画 |
|---|---|---|---|
| 原理 | 涂鸦 PNG + 提示词 → 扩散视频模型 | 人形检测→分割→骨骼估计→BVH 动作重定向→ARAP 网格形变 | 精灵整体做缩放/位移/旋转/果冻抖动 + 粒子特效（纯 Flutter） |
| 效果 | ⭐⭐⭐⭐⭐ "活灵活现"天花板，任意内容都能动 | ⭐⭐⭐⭐ 让画里的"小人"真的跳舞走路，风格保留极好 | ⭐⭐ "会动"但不算"活"，更像贴纸特效 |
| 内容限制 | 无（动物、房子、火箭都行） | **仅限人形角色**（一头两臂两腿），动物场景直接失效 | 无 |
| 单次成本 | ¥1.5~7.5/条（详见 §4） | 服务器 GPU 摊销，边际成本 ≈ ¥0.01 级 | **¥0** |
| 延迟 | 30 秒~2 分钟（异步任务轮询） | 5~15 秒 | **<1 秒，即时反馈** |
| 离线可用 | ❌ | ❌（除非上端侧模型，工程量大） | ✅ |
| 合规负担 | 生成内容标识、内容审核都要做 | 自部署内容不出域，负担最小 | 无 |
| 依据 | 可灵/豆包公开定价（2026-09 核实） | github.com/facebookresearch/AnimatedDrawings，**MIT 许可可商用**（2023-04 从 CC 改为 MIT），SIGGRAPH 2023 论文，12.8k stars | Flutter Animation API |

**推荐组合拳（本项目核心方案）：**

```
路线 C —— 免费层：任何涂鸦立刻能动（果冻跳、摇摆、旋转入场），即时满足感，零成本
路线 B —— 主路径：检测到人形角色时提示"它想跳舞！"，自部署服务生成骨骼动画
路线 A —— 付费亮点："许愿变身"大魔法，云端生成真正惊艳的 5 秒动画
```

这样设计的产品逻辑是：**免费用户永远有得玩（C+B），付费用户买到惊叹（A），成本曲线和收入曲线挂钩，而不是和用户量挂钩。**

### 3.6 路线 B 的工程细节（值得单独说）

- 官方栈是 Python 3.8 + TorchServe + Docker，检测/姿态模型来自 OpenMMLab（Apache 2.0）。
- 端侧跑不现实（模型包大、移动端算力浪费在推理上），**正确姿势是自部署一台 GPU 服务器**（或按量租用），客户端只传图收视频。
- 已知短板：非人形（恐龙、小猫）直接不适用。缓解：路线 A 兜底，或在 UI 上引导（"画一个小朋友试试！"）。
- 维护成本：镜像 + 模型更新基本一次性投入，之后很稳（项目 2025-09 后 archived，但功能完整、算法成熟，作为内部服务够用）。

## 4. 成本模型（拿计算器说话）

单次"许愿动画"全链路成本（路线 A，2026-09 实时价格）：

| 项目 | 低价档 | 高价档 |
|---|---|---|
| ASR + LLM + 安全过滤 | ¥0.005 | ¥0.01 |
| 豆包 Seedance 1.0-pro 720p 5s（¥15/M token，102,960 tokens） | **¥1.54** | — |
| 可灵 2.6 图生视频 720p 5s（¥0.3/秒） | **¥1.5** | — |
| 可灵 3.0 720p 5s（¥0.6~0.9/秒） | — | **¥3.0~4.5** |
| Seedance 2.5 720p 5s | — | ¥7.56 |
| **单次合计** | **≈¥1.5** | **≈¥4.5~7.5** |

规模测算（假设 60% 动画走免费层 B/C，40% 走云端 A）：

| 规模 | 日动画量 | 云端占比 | 日成本 | 月成本 |
|---|---|---|---|---|
| 冷启动（500 DAU × 3 次） | 1,500 | 40% | ¥900 | ¥2.7 万 |
| 起量（5,000 DAU × 3 次） | 15,000 | 40% | ¥9,000 | ¥27 万 |
| 爆发（50,000 DAU × 3 次） | 150,000 | 40% | ¥90,000 | **¥270 万** |

**结论（难听但必须说）：**
- 如果所有用户无限用云端视频，这个产品每多一个用户就多赔钱，DAU 越高死得越快——这不是技术问题，是自杀式商业模式。
- 必须用配额制：免费用户每日 1~2 次云端魔法（成本 ≈ ¥3~6/用户/月），超出引导订阅（¥25/月含 30 次，毛利依然健康）或用免费的 B/C 路线。
- 端侧 C 路线 + 自部署 B 路线承担 80% 以上的动画量，把云端 A 做成"惊喜"而不是"默认"，成本结构立刻从"悬崖"变"缓坡"。
- 视频模型价格处于快速下降通道（一年内单价约降 50%+），成本问题会随时间缓解，但产品第一天就要按上面的纪律设计。

## 5. 合规与安全（国内上架的真正硬门槛，比技术难）

| 风险 | 要求 | 应对 |
|---|---|---|
| 生成式 AI 监管 | 《生成式人工智能服务管理暂行办法》：算法备案 + 生成内容标识（AI 生成视频需显式/隐式水印） | 接入的云端模型（可灵/豆包）自带标识能力；自部署 B 路线输出也打"AI 生成"角标；上线前完成深度合成算法备案 |
| 未成年人保护 | 个保法：14 岁以下需监护人同意；儿童个人信息网络保护规定 | 首次启动家长门（算术题/长按确认）+ 监护人同意流程；儿童数据最小化收集 |
| 内容安全 | 儿童场景零容忍出事 | 三层过滤：本地词库 → LLM 安全审查 → 云端模型自带审核；所有提示词白名单化（只允许描述画面，不允许出现敏感词） |
| App Store 儿童类别 | 指南 29：禁止第三方广告、行为追踪、限制 IAP | 少接 SDK（分析用苹果原生或自建）；广告不做；IAP 走订阅制 |
| 算力滥用 | 孩子狂点"许愿"把服务器点破产 | 端侧节流 + 每日配额 + 家长确认大额消耗 |

**建议**：MVP 先在 TestFlight / 桌面端 / 国内应用市场灰度，App Store 正式上架放在完成备案之后。

## 6. 系统架构

```
┌─────────────────────────────────────────────────┐
│            Flutter 客户端（四端同源）              │
│  画板/涂色 │ 相机 │ 录音 │ TTS │ 本地动画引擎(C)    │
└──────────────┬──────────────────────────────────┘
               │ HTTPS（自有网关，不直连模型 API）
┌──────────────▼──────────────────────────────────┐
│            轻量后端网关（Go/Node）                 │
│  鉴权/家长门 │ 配额计费 │ 内容安全 │ 任务队列        │
└───────┬──────────────┬───────────────┬──────────┘
        │              │               │
┌───────▼─────┐ ┌──────▼──────┐ ┌──────▼────────┐
│ ASR/LLM/TTS │ │ 图像生成/    │ │ AnimatedDrawings│
│ (豆包/GLM,   │ │ 图生视频 API │ │ 自部署 GPU Worker│
│  聚合调用)   │ │ (可灵/豆包)  │ │ (路线 B)        │
└─────────────┘ └─────────────┘ └───────────────┘
```

要点：
- **客户端绝不直连模型 API**（密钥安全 + 统一计费审核 + 可换供应商）。模型层全部走网关聚合，供应商可插拔——视频模型一年一降价，别把代码焊死在一家上。
- MVP 阶段网关可以先用云函数/Serverless 起步，成本几乎为零。
- 作品存储：本地（四端）为主，云端相册（家长分享）为增值项，后期再做。
